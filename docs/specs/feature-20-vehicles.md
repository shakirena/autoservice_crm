# Спецификация: Feature #20 — База автомобилей

**Эпик:** #20 — База автомобилей — привязка к клиенту, CRUD, история
**Статус:** Ready for Dev
**Дата:** 2026-05-20
**Автор:** analyst-agent

---

## 1. Цель

Реализовать модуль управления автомобилями автосервиса: просмотр списка всех автомобилей со ссылкой на клиента, добавление и редактирование автомобиля. Модуль доступен ролям admin и manager (CRUD). Роли mechanic и client доступа к этому модулю не имеют.

---

## 2. Функциональные требования (FR)

| ID    | Требование |
|-------|-----------|
| FR-1  | Система отображает список всех автомобилей в виде таблицы на маршруте `/dashboard/vehicles`. |
| FR-2  | Таблица содержит колонки: марка (make), модель (model), год выпуска (year), VIN, гос. номер (licensePlate), ссылка на клиента. |
| FR-3  | Список отсортирован по createdAt по убыванию (новые — сверху). |
| FR-4  | Ссылка на клиента в таблице ведёт к данным клиента (fullName), полученным через clientId. |
| FR-5  | Пользователь с ролью admin или manager может добавить автомобиль через форму. |
| FR-6  | Форма добавления содержит поля: марка (обязательно), модель (обязательно), год выпуска (обязательно), VIN (обязательно), гос. номер (обязательно), выбор клиента из списка (обязательно). |
| FR-7  | VIN проходит валидацию: ровно 17 символов, латиница (A–H, J–N, P–R, Z) и цифры (0–9), без I, O, Q. |
| FR-8  | Год выпуска проходит валидацию: числовое значение в диапазоне 1900 — текущий год. |
| FR-9  | При создании автомобиля в Firestore сохраняются поля: clientId, make, model, year, vin, licensePlate, createdAt (server timestamp). |
| FR-10 | Пользователь с ролью admin или manager может редактировать поля существующего автомобиля. |
| FR-11 | Форма редактирования предзаполнена текущими данными автомобиля. |
| FR-12 | После сохранения (create или update) таблица обновляется без перезагрузки страницы. |
| FR-13 | Маршрут `/dashboard/vehicles` защищён: доступ только авторизованным пользователям с ролями admin, manager. |

## 3. Нефункциональные требования (NFR)

| ID    | Требование |
|-------|-----------|
| NFR-1 | Время первоначальной загрузки списка автомобилей — не более 2 секунд при наличии до 1000 записей. |
| NFR-2 | Все запросы к Firestore защищены Security Rules: `request.auth != null` как базовое условие. |
| NFR-3 | Операции записи (create, update) разрешены только для ролей admin и manager (`request.auth.token.role in ['admin', 'manager']`). |
| NFR-4 | Компоненты не импортируют Firestore SDK напрямую — только через сервисный слой `src/services/vehiclesService.js`. |
| NFR-5 | Формы реализованы через React Hook Form, без неконтролируемых input-элементов. |
| NFR-6 | E2E-селекторы используют только атрибут `data-testid`, без CSS-классов и XPath. |
| NFR-7 | Серверное состояние (список автомобилей) управляется через TanStack React Query; UI-состояние (модалки) — через useState. |

## 5. Acceptance Criteria по Stories

### S-1: Страница списка автомобилей (#39)

**Given** пользователь с ролью admin или manager авторизован и переходит на `/dashboard/vehicles`
**When** страница загружается
**Then** отображается таблица всех автомобилей с колонками: марка, модель, год, VIN, гос. номер, ссылка на клиента; таблица отсортирована по createdAt по убыванию

### S-2: Добавление автомобиля (#40)

**Given** пользователь с ролью admin или manager находится на `/dashboard/vehicles`
**When** нажимает «Добавить автомобиль», заполняет форму (марка, модель, год, VIN, гос. номер обязательны; клиент выбирается из выпадающего списка) и подтверждает создание
**Then** новый документ сохраняется в Firestore `vehicles/{id}` с полями clientId, make, model, year, vin, licensePlate, createdAt; форма закрывается; таблица обновляется без перезагрузки страницы

### S-3: Редактирование автомобиля (#41)

**Given** пользователь с ролью admin или manager видит автомобиль в таблице `/dashboard/vehicles`
**When** нажимает кнопку редактирования, изменяет одно или несколько полей и сохраняет
**Then** документ `vehicles/{id}` обновляется в Firestore; форма закрывается; таблица отражает новые данные без перезагрузки страницы

## 6. Архитектура и технические детали

### Firestore

```
vehicles/{id}
  clientId:     string   // ссылка на clients/{clientId}
  make:         string   // марка, обязательно
  model:        string   // модель, обязательно
  year:         number   // год выпуска, 1900–текущий год
  vin:          string   // 17 символов, без I/O/Q
  licensePlate: string   // гос. номер, обязательно
  createdAt:    timestamp
```

### Структура файлов

```
src/
  services/
    vehiclesService.js       # getVehicles(), createVehicle(data), updateVehicle(id, data)
  hooks/
    useVehicles.js           # useQuery → список всех автомобилей
    useCreateVehicle.js      # useMutation → создание
    useUpdateVehicle.js      # useMutation → обновление
  features/
    vehicles/
      VehicleTable.jsx       # таблица автомобилей (skeleton, empty state)
      VehicleRow.jsx         # строка таблицы; кнопка редактирования скрыта для mechanic
      VehicleForm.jsx        # форма create/edit (React Hook Form), режим через проп vehicle
  pages/
    dashboard/
      VehiclesPage.jsx       # /dashboard/vehicles
```

### Firestore Security Rules (фрагмент)

```javascript
match /vehicles/{vehicleId} {
  allow read: if request.auth != null &&
    request.auth.token.role in ['admin', 'manager'];
  allow create, update: if request.auth != null &&
    request.auth.token.role in ['admin', 'manager'];
  allow delete: if false; // удаление не предусмотрено в этом эпике
}
```
