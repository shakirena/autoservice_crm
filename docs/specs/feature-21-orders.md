## Обзор

Заказ-наряд — центральная сущность CRM. Фиксирует факт выполнения работ: какому клиенту, на каком автомобиле, какие работы выполнены, стоимость и итоговый статус.

**Роли и доступ:**

| Роль     | Создание | Просмотр списка | Просмотр деталей | Смена статуса |
|----------|----------|-----------------|------------------|---------------|
| admin    | да       | да              | да               | да            |
| manager  | да       | да              | да               | да            |
| mechanic | нет      | да (read-only)  | да               | да (completed)|
| client   | нет      | нет             | нет              | нет           |

## Функциональные требования

### FR-1 — Список заказов (/dashboard/orders)

- FR-1.1: Страница доступна пользователям с ролями admin, manager, mechanic.
- FR-1.2: Отображается таблица с колонками: Клиент, Автомобиль, Статус, Дата, Сумма (₼).
- FR-1.3: Данные загружаются из коллекции Firestore `orders`, сортировка по `date` по убыванию.
- FR-1.4: Фильтр по статусу: «Все», «Черновик» (draft), «В работе» (in_progress), «Выполнен» (completed).
- FR-1.5: Кнопка «Создать заказ» видна только для admin и manager.
- FR-1.6: Каждая строка — ссылка на страницу деталей заказа (/dashboard/orders/:id).
- FR-1.7: Пустое состояние: сообщение «Нет заказов» при пустом результате.

### FR-2 — Создание заказа — Шаг 1: Выбор клиента

- FR-2.1: Доступ: admin и manager.
- FR-2.2: Поиск клиента из существующей базы (#19) по имени или номеру телефона.
- FR-2.3: Выбор клиента обязателен; нельзя перейти на шаг 2 без выбора.

### FR-3 — Создание заказа — Шаг 2: Выбор автомобиля

- FR-3.1: Отображается список автомобилей, привязанных к выбранному клиенту (#20).
- FR-3.2: Формат: «Марка Модель Год».
- FR-3.3: Выбор автомобиля обязателен.

### FR-4 — Создание заказа — Шаг 3: Выбор узла

- FR-4.1: Выбор узла автомобиля из фиксированного enum vehicleComponent.
- FR-4.2: Значения enum: engine, gearbox, suspension, brakes, electrics, tires, body, other.
- FR-4.3: Русские метки: Двигатель, КПП, Подвеска, Тормоза, Электрика, Шины, Кузов, Прочее.

### FR-5 — Создание заказа — Шаг 4: Технические параметры узла

- FR-5.1: Форма параметров генерируется динамически в зависимости от выбранного узла (FR-4).
- FR-5.2: Параметры сохраняются в поле `componentParams` (object) документа заказа.
- FR-5.3: Состав полей для каждого узла описан в разделе [vehicleComponent — схема параметров](#vehiclecomponent--схема-параметров).

### FR-6 — Создание заказа — Шаг 5: Выбор работ

- FR-6.1: Отображается список работ из справочника (#18) в виде чекбоксов.
- FR-6.2: Каждый чекбокс показывает название работы и цену в ₼.
- FR-6.3: Можно выбрать несколько работ одновременно.
- FR-6.4: Выбранные работы сохраняются как массив `services[]`: [{serviceId, name, price}].

### FR-7 — Создание заказа — Шаг 6: Дата и сумма

- FR-7.1: Поле выбора даты (по умолчанию — текущая дата).
- FR-7.2: `totalAmount` автоматически вычисляется как сумма цен выбранных услуг.
- FR-7.3: Менеджер может вручную скорректировать `totalAmount`.
- FR-7.4: Сумма отображается в ₼.

### FR-8 — Создание заказа — Шаг 7: Предпросмотр и сохранение

- FR-8.1: Экран предпросмотра показывает все данные из предыдущих шагов.
- FR-8.2: Кнопка «Сохранить» создаёт документ в `orders/{id}` со статусом `draft`.
- FR-8.3: После сохранения пользователь перенаправляется на /dashboard/orders/:id.
- FR-8.4: Кнопка «Назад» доступна на каждом шаге (кроме первого).

### FR-9 — Страница деталей заказа (/dashboard/orders/:id)

- FR-9.1: Доступна для admin, manager, mechanic.
- FR-9.2: Отображаются секции: Клиент, Автомобиль, Узел, Технические параметры, Работы, Итоговая сумма (₼), Статус.
- FR-9.3: Список работ отображается как таблица: Название, Цена (₼).
- FR-9.4: Статус отображается как цветной badge: draft=серый, in_progress=жёлтый, completed=зелёный.
- FR-9.5: Skeleton loader пока данные загружаются.
- FR-9.6: Кнопка «Изменить статус» (логика — FR-10).

### FR-10 — Смена статуса заказа

- FR-10.1: Механик видит кнопку «Отметить выполненным» на странице заказа.
- FR-10.2: Кнопка неактивна, если status === 'completed'.
- FR-10.3: Перед сменой статуса отображается диалог подтверждения.
- FR-10.4: После подтверждения: `status` → 'completed', `completedAt` → Timestamp.now().
- FR-10.5: Admin и manager могут менять статус с 'draft' на 'in_progress' и обратно.
- FR-10.6: Страница обновляется без полного reload (TanStack Query invalidation).

## Нефункциональные требования

### NFR-1 — Производительность

- NFR-1.1: Список заказов загружается за ≤ 2 секунды (до 500 документов).
- NFR-1.2: Фильтрация по статусу — клиентская, без дополнительных запросов к Firestore.
- NFR-1.3: Wizard не производит запросы к Firestore до финального шага (кроме useClients, useVehiclesByClient, useServices).

### NFR-2 — RBAC и безопасность

- NFR-2.1: Firestore Security Rules: `request.auth != null` — baseline для всех операций.
- NFR-2.2: Создание заказа (write): `request.auth.token.role in ['admin', 'manager']`.
- NFR-2.3: Чтение заказа (read): `request.auth.token.role in ['admin', 'manager', 'mechanic']`.
- NFR-2.4: Обновление статуса механиком: разрешено только обновление полей `status` и `completedAt`.
- NFR-2.5: Роль `client` не имеет доступа к коллекции `orders` через веб-приложение.

### NFR-3 — Целостность данных

- NFR-3.1: `createdBy` заполняется автоматически из `auth.currentUser.uid` — клиент не может подставить чужой uid.
- NFR-3.2: `totalAmount` валидируется как положительное число на клиенте и в Firestore Rules (amount >= 0).
- NFR-3.3: Поля `clientId` и `vehicleId` обязательны; документ не сохраняется без них.
- NFR-3.4: `services[]` может быть пустым массивом (заказ без работ возможен), но `totalAmount` тогда равен 0.

### NFR-4 — UX

- NFR-4.1: Wizard сохраняет данные предыдущих шагов при навигации назад.
- NFR-4.2: Кнопка «Сохранить» блокируется во время записи в Firestore (loading state).
- NFR-4.3: При ошибке записи отображается toast-уведомление с текстом ошибки.

## Схема данных Firestore

### Коллекция: `orders/{id}`

```
{
  clientId:         string,        // UID клиента из коллекции clients
  vehicleId:        string,        // UID автомобиля из коллекции vehicles
  vehicleComponent: string,        // enum: engine|gearbox|suspension|brakes|electrics|tires|body|other
  componentParams:  object,        // динамический объект — состав зависит от vehicleComponent
  services:         array,         // [{serviceId: string, name: string, price: number}]
  totalAmount:      number,        // итоговая сумма в ₼ (≥ 0)
  date:             Timestamp,     // дата выполнения работ
  createdBy:        string,        // uid пользователя, создавшего заказ
  status:           string,        // 'draft' | 'in_progress' | 'completed'
  completedAt:      Timestamp|null, // Timestamp.now() при переходе в 'completed'
  createdAt:        Timestamp      // serverTimestamp() при создании
}
```

## vehicleComponent — схема параметров

### engine (Двигатель)

```js
componentParams: {
  volume:        string,  // Объём двигателя, напр. "2.0"
  oilType:       string,  // Тип масла, напр. "синтетика"
  saeSpec:       string,  // SAE спецификация, напр. "5W-40"
  mileage:       number,  // Пробег (км)
}
```

### gearbox (КПП)

```js
componentParams: {
  gearboxType:   string,  // enum: "МКПП" | "АКПП" | "Вариатор"
  oilVolume:     string,  // Объём масла КПП, напр. "2.5 л"
  oilBrand:      string,  // Марка масла
}
```

### suspension (Подвеска)

```js
componentParams: {
  defects:       string,  // Описание дефектов (свободный текст)
  mileage:       number,  // Пробег (км)
  shockType:     string,  // Тип амортизаторов, напр. "масляные", "газовые"
}
```

### brakes (Тормоза)

```js
componentParams: {
  padType:       string,  // Тип колодок, напр. "органические", "металлизированные"
  discDiameter:  number,  // Диаметр дисков (мм)
  axle:          string,  // Ось: "передняя" | "задняя" | "обе"
}
```

### electrics (Электрика)

```js
componentParams: {
  description:   string,  // Описание неисправности
  errorCode:     string,  // Код ошибки OBD (опционально)
}
```

### tires (Шины)

```js
componentParams: {
  tireSize:      string,  // Размер шин, напр. "205/55 R16"
  tireType:      string,  // Тип: "летние" | "зимние" | "всесезонные"
}
```

### body (Кузов)

```js
componentParams: {
  damages:       string,  // Перечень повреждений
  description:   string,  // Дополнительное описание работ
}
```

### other (Прочее)

```js
componentParams: {
  description:   string,  // Свободный текст
}
```

## Acceptance Criteria

### #42 — Список заказов

**Given** пользователь с ролью admin, manager или mechanic открывает /dashboard/orders
**When** страница загружается
**Then** отображается таблица заказов (клиент, автомобиль, статус, дата, сумма) с фильтром по статусу; кнопка «Создать заказ» видна только admin и manager

### #43 — Создание заказа (wizard)

**Given** менеджер открывает /dashboard/orders/new
**When** проходит все 7 шагов wizard и нажимает «Сохранить»
**Then** создаётся документ в orders/{id} со статусом 'draft' и пользователь перенаправляется на страницу деталей заказа

### #44 — Страница деталей заказа

**Given** пользователь с ролью admin, manager или mechanic переходит по ссылке на заказ
**When** страница /dashboard/orders/:id загружается
**Then** отображаются все данные заказа: клиент, автомобиль, узел, тех. параметры, список работ с ценами, дата, итоговая сумма и текущий статус

### #45 — Смена статуса механиком

**Given** механик находится на странице заказа со статусом 'in_progress'
**When** нажимает кнопку «Отметить выполненным» и подтверждает действие
**Then** статус заказа меняется на 'completed', поле completedAt записывается как Timestamp.now(), страница обновляется без reload

## Вне Scope

- **Android-приложение** — просмотр заказов клиентом (#23)
- **Оплата и касса** — интеграция с платёжными системами
- **PDF-экспорт** — печать заказ-наряда
- **Поиск по тексту** — полнотекстовый поиск заказов
- **Пагинация** — постраничная загрузка (достаточно клиентской фильтрации)
- **Создание клиента из wizard** — только выбор из существующих (#19)
- **Создание автомобиля из wizard** — только выбор из существующих (#20)
- **Удаление заказов** — не предусмотрено в текущей версии
- **История изменений статуса** — аудит-лог
- **Уведомления** — push/email при смене статуса
