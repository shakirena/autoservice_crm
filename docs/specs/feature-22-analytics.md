# Feature #22 — Отчёты и аналитика (admin)

_Создан: 2026-05-21_

---

## Функциональные требования (FR)

### Story #46 — Дашборд KPI-карточек аналитики

**FR-1.** Маршрут `/dashboard/analytics` доступен только пользователям с ролью `admin`.
**FR-2.** На странице отображаются 4 KPI-карточки: общая выручка (₼), количество заказов, количество уникальных клиентов, средний чек (₼).
**FR-3.** Фильтр периода предоставляет 4 пресета: сегодня / неделя / месяц / всё время.
**FR-4.** При смене периода все 4 карточки пересчитываются без перезагрузки страницы.
**FR-5.** Данные загружаются единым запросом к коллекции `orders` (без серверной фильтрации по дате) и фильтруются на клиенте.

### Story #47 — Отчёт по выручке с топом услуг

**FR-6.** В секции «Выручка» отображается bar-chart или line-chart выручки по дням за выбранный период (ось X — даты, ось Y — сумма в ₼).
**FR-7.** Отображается таблица «Топ-5 услуг по выручке» (название, сумма ₼).
**FR-8.** Отображается таблица «Топ-5 услуг по количеству» (название, кол-во использований).
**FR-9.** Услуги агрегируются из поля `orders[].services[]` (каждый элемент содержит `name` и `price`).
**FR-10.** Секция использует те же данные orders, что уже загружены для KPI, — без повторных Firestore-запросов.

### Story #48 — Отчёт по активности сотрудников

**FR-11.** В секции «Сотрудники» отображается таблица: сотрудник (displayName), кол-во заказов, сумма выручки (₼).
**FR-12.** Таблица сортируется по выручке по убыванию.
**FR-13.** Данные фильтруются по тому же пресету периода, что выбран в общем фильтре.
**FR-14.** Для получения `displayName` по `uid` (поле `createdBy` в orders) используется hook `useUsers` из feature #17 — join на клиенте через Map.

## Нефункциональные требования (NFR)

**NFR-1. Клиентская агрегация.** Все вычисления (суммы, группировки, топы) производятся на клиенте после единственной загрузки коллекции `orders`. Cloud Functions не используются.
**NFR-2. Один Firestore-запрос.** Вся аналитика строится на одном `getDocs(collection(db, 'orders'))` без серверных фильтров (фильтрация по дате — клиентская).
**NFR-3. Доступ.** Firestore rules: `read` разрешён только при `request.auth.token.role == 'admin'`.
**NFR-4. Нет real-time.** Данные загружаются при маунте страницы (useQuery без `onSnapshot`).
**NFR-5. Производительность.** При до 10 000 документов в коллекции orders UI должен оставаться отзывчивым (агрегация синхронная, данные в памяти).
**NFR-6. Валюта.** Все денежные значения отображаются с символом ₼ через `toLocaleString('ru-RU')`.

## Acceptance Criteria

### #46 — Дашборд KPI-карточек аналитики
**Given** admin открывает /dashboard/analytics и выбирает период «Неделя»
**When** страница загружает данные из коллекции orders
**Then** отображаются 4 карточки: общая выручка (₼), кол-во заказов, кол-во уникальных клиентов, средний чек — все пересчитаны за выбранный период

### #47 — Отчёт по выручке с топом услуг
**Given** admin находится на /dashboard/analytics и данные orders загружены
**When** отображается секция «Отчёт по выручке»
**Then** показан bar/line chart выручки по дням за выбранный период, таблица топ-5 услуг по сумме выручки и таблица топ-5 услуг по количеству использований

### #48 — Отчёт по активности сотрудников
**Given** admin находится на /dashboard/analytics с выбранным периодом
**When** отображается секция «Сотрудники»
**Then** показана таблица: сотрудник (displayName из users), кол-во заказов, сумма выручки (₼) — отсортированная по выручке убыванию, данные соответствуют выбранному периоду

## Вне Scope

- Экспорт Excel/PDF
- Real-time обновление данных (onSnapshot)
- Кастомный диапазон дат (только 4 пресета)
- Детальный список заказов конкретного сотрудника
- Сравнение периодов (текущий vs предыдущий)
- Фильтрация по конкретному клиенту в разделе выручки
- Клиентская база (новые vs повторные клиенты) — откладывается за MVP аналитики
