# Спецификация: Feature #19 — База клиентов

**Эпик:** #19 — База клиентов — список, создание, редактирование, поиск
**Статус:** Ready for Dev
**Дата:** 2026-05-20
**Автор:** analyst-agent

---

## 1. Цель

Реализовать модуль управления клиентами автосервиса: просмотр списка, создание, редактирование и поиск клиентов. Модуль доступен ролям admin и manager (CRUD), mechanic (только чтение). Роль client доступа не имеет.

---

## 2. Функциональные требования (FR)

| ID    | Требование |
|-------|-----------|
| FR-1  | Система отображает список всех клиентов в виде таблицы на маршруте `/dashboard/clients`. |
| FR-2  | Таблица содержит колонки: ФИО (fullName), телефон (phone), email, дата создания (createdAt). |
| FR-3  | Список отсортирован по createdAt по убыванию (новые — сверху). |
| FR-4  | Пользователь с ролью admin или manager может создать нового клиента через форму. |
| FR-5  | Форма создания содержит поля: ФИО (обязательно), телефон (обязательно), email (опционально). |
| FR-6  | При создании клиента в Firestore сохраняются поля: fullName, phone, email, createdAt (server timestamp), createdBy (uid текущего пользователя). |
| FR-7  | Пользователь с ролью admin или manager может редактировать данные существующего клиента. |
| FR-8  | Форма редактирования предзаполнена текущими данными клиента. |
| FR-9  | Пользователь может искать клиентов по ФИО или номеру телефона через текстовое поле. |
| FR-10 | Поиск выполняется на стороне клиента (client-side), без повторных запросов к Firestore, без учёта регистра. |
| FR-11 | Поиск активируется при вводе от 2 символов, с debounce 300 мс. |
| FR-12 | Маршрут `/dashboard/clients` защищён: доступ только авторизованным пользователям с ролями admin, manager, mechanic. |

---

## 3. Нефункциональные требования (NFR)

| ID    | Требование |
|-------|-----------|
| NFR-1 | Время первоначальной загрузки списка клиентов — не более 2 секунд при наличии до 1000 записей. |
| NFR-2 | Все запросы к Firestore защищены Security Rules: `request.auth != null` как базовое условие. |
| NFR-3 | Операции записи (create, update) разрешены только для ролей admin и manager (`request.auth.token.role in ['admin', 'manager']`). |
| NFR-4 | Компоненты не импортируют Firestore SDK напрямую — только через сервисный слой `src/services/clientsService.js`. |
| NFR-5 | Формы реализованы через React Hook Form, без неконтролируемых input-элементов. |
| NFR-6 | E2E-селекторы используют только атрибут `data-testid`, без CSS-классов и XPath. |
| NFR-7 | Серверное состояние (список клиентов) управляется через TanStack React Query; UI-состояние (строка поиска) — через useState/Zustand. |

## 5. Acceptance Criteria по Stories

### S-1: Таблица клиентов (#35)

**Given** пользователь с ролью admin, manager или mechanic авторизован и переходит на `/dashboard/clients`
**When** страница загружается
**Then** отображается таблица со всеми клиентами (ФИО, телефон, email), отсортированная по дате создания (убывание)

### S-2: Создание клиента (#36)

**Given** пользователь с ролью admin или manager авторизован и находится на `/dashboard/clients`
**When** нажимает кнопку «Добавить клиента», заполняет форму (ФИО обязательно, телефон обязательно, email опционально) и подтверждает создание
**Then** новый документ сохраняется в Firestore `clients/{id}` с полями fullName, phone, email, createdAt, createdBy; форма закрывается; таблица обновляется без перезагрузки страницы

### S-3: Редактирование клиента (#37)

**Given** пользователь с ролью admin или manager авторизован и видит клиента в таблице `/dashboard/clients`
**When** нажимает кнопку редактирования клиента, изменяет одно или несколько полей и сохраняет
**Then** документ `clients/{id}` обновляется в Firestore; форма закрывается; таблица отражает новые данные без перезагрузки страницы

### S-4: Поиск клиентов (#38)

**Given** пользователь с ролью admin, manager или mechanic находится на `/dashboard/clients` и таблица загружена
**When** вводит текст в поле поиска (минимум 2 символа)
**Then** таблица немедленно (client-side, без запроса к Firestore) отображает только строки, у которых fullName или phone содержат введённую строку (без учёта регистра)

## 6. Архитектура и технические детали

### Firestore

```
clients/{id}
  fullName:  string   // обязательно
  phone:     string   // обязательно
  email:     string   // опционально, может быть ""
  createdAt: timestamp
  createdBy: string   // uid пользователя-создателя
```

### Структура файлов

```
src/
  services/
    clientsService.js       # getClients(), createClient(data), updateClient(id, data)
  hooks/
    useClients.js           # useQuery + useClients hook
    useCreateClient.js      # useMutation + optimistic update
    useUpdateClient.js      # useMutation
  features/
    clients/
      ClientsTable.jsx      # таблица клиентов
      ClientForm.jsx        # форма создания/редактирования (переиспользуется)
      ClientsSearch.jsx     # поле поиска с debounce
  pages/
    ClientsPage.jsx         # /dashboard/clients
```

### Firestore Security Rules (фрагмент)

```javascript
match /clients/{clientId} {
  allow read: if request.auth != null &&
    request.auth.token.role in ['admin', 'manager', 'mechanic'];
  allow create, update: if request.auth != null &&
    request.auth.token.role in ['admin', 'manager'];
  allow delete: if false; // удаление не предусмотрено в этом эпике
}
```

### data-testid атрибуты

| Атрибут | Элемент |
|---------|---------|
| `clients-table` | Таблица клиентов |
| `client-row-{id}` | Строка клиента в таблице |
| `create-client-btn` | Кнопка «Добавить клиента» |
| `client-form` | Форма создания/редактирования |
| `submit-client-btn` | Кнопка подтверждения формы |
| `edit-client-btn-{id}` | Кнопка редактирования клиента |
| `clients-search-input` | Поле поиска |
