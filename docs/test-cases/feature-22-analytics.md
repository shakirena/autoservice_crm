## TC-22-001: KPI-карточки отображаются на странице /dashboard/analytics

**Priority:** High
**Type:** Functional (Happy Path)
**Related AC:** US-22-1 (#46)

### Preconditions
- Пользователь авторизован с ролью admin
- Firestore коллекция `orders` содержит 5 заказов за последние 30 дней с разными clientId и totalAmount

### Steps
| Step | Action | Expected Result |
|------|--------|----------------|
| 1 | Перейти на /dashboard/analytics | Страница загружается без ошибок; data-testid="analytics-page" присутствует |
| 2 | Дождаться завершения загрузки (skeleton исчезает) | Spinner/skeleton более не виден |
| 3 | Проверить наличие data-testid="kpi-revenue" | Карточка «Общая выручка» присутствует и содержит число с символом ₼ |
| 4 | Проверить наличие data-testid="kpi-orders" | Карточка «Кол-во заказов» присутствует и содержит число 5 |
| 5 | Проверить наличие data-testid="kpi-clients" | Карточка «Клиентов» присутствует и содержит число уникальных clientId |
| 6 | Проверить наличие data-testid="kpi-avg-check" | Карточка «Средний чек» присутствует и содержит число с символом ₼ |
| 7 | Проверить наличие data-testid="period-filter" | Фильтр периода присутствует на странице |
| 8 | Убедиться, что фильтр предлагает 4 варианта | Варианты: «Сегодня», «Неделя», «Месяц», «Всё время» |

### Expected Result
Все 4 KPI-карточки (выручка, заказов, клиентов, средний чек) отображаются с корректными значениями. Фильтр периода присутствует с четырьмя пресетами.

### Test Data
```
orders: [
  { id: "o1", clientId: "c1", totalAmount: 500, date: "2026-05-10", status: "completed", services: [] },
  { id: "o2", clientId: "c2", totalAmount: 300, date: "2026-05-12", status: "completed", services: [] },
  { id: "o3", clientId: "c1", totalAmount: 200, date: "2026-05-15", status: "completed", services: [] },
  { id: "o4", clientId: "c3", totalAmount: 400, date: "2026-05-18", status: "completed", services: [] },
  { id: "o5", clientId: "c4", totalAmount: 600, date: "2026-05-20", status: "completed", services: [] }
]
// expected: revenue=2000, orders=5, clients=4, avgCheck=400
```

## TC-22-002: Фильтр периода пересчитывает KPI-карточки без перезагрузки страницы

**Priority:** High
**Type:** Functional
**Related AC:** US-22-1 (#46)

### Preconditions
- Пользователь авторизован с ролью admin
- Страница /dashboard/analytics открыта, данные загружены (пресет «Всё время»)
- Firestore содержит 8 заказов: 3 за сегодня, 2 за последние 7 дней (без сегодня), 3 старше 7 дней

### Steps
| Step | Action | Expected Result |
|------|--------|----------------|
| 1 | Считать значение data-testid="kpi-orders" при пресете «Всё время» | Карточка показывает 8 |
| 2 | Кликнуть на data-testid="period-filter" и выбрать «Сегодня» | Фильтр применяется без перезагрузки страницы |
| 3 | Считать значение data-testid="kpi-orders" | Карточка показывает 3 (только заказы за сегодня) |
| 4 | Убедиться, что в Network нет нового запроса к Firestore | Дополнительных Firestore-вызовов нет; фильтрация клиентская |
| 5 | Выбрать пресет «Неделя» | Фильтр применяется |
| 6 | Считать значение data-testid="kpi-orders" | Карточка показывает 5 (сегодня + 2 за неделю) |
| 7 | Выбрать пресет «Месяц» | Фильтр применяется |
| 8 | Считать значение data-testid="kpi-orders" | Карточка показывает 8 (все заказы за 30 дней) |

### Expected Result
При смене пресета периода все KPI-карточки пересчитываются мгновенно (client-side), без нового обращения к Firestore. Каждый пресет отображает корректное количество.

### Test Data
```
orders (сегодня 2026-05-21):
  { id: "t1", date: "2026-05-21", totalAmount: 100, clientId: "c1" }
  { id: "t2", date: "2026-05-21", totalAmount: 150, clientId: "c2" }
  { id: "t3", date: "2026-05-21", totalAmount: 200, clientId: "c3" }
orders (последние 7 дней):
  { id: "w1", date: "2026-05-17", totalAmount: 300, clientId: "c4" }
  { id: "w2", date: "2026-05-19", totalAmount: 250, clientId: "c5" }
orders (старше 7 дней):
  { id: "m1", date: "2026-05-01", totalAmount: 400, clientId: "c6" }
  { id: "m2", date: "2026-05-05", totalAmount: 350, clientId: "c7" }
  { id: "m3", date: "2026-05-08", totalAmount: 180, clientId: "c8" }

## TC-22-003: RBAC — не-admin пользователь заблокирован на /dashboard/analytics

**Priority:** High
**Type:** Security / RBAC
**Related AC:** US-22-1 (#46), FR-1, NFR-3

### Preconditions
- Пользователи с ролями manager и mechanic авторизованы в отдельных сессиях

### Steps
| Step | Action | Expected Result |
|------|--------|----------------|
| 1 | Войти как manager (role: "manager") | Авторизация прошла успешно |
| 2 | Перейти на /dashboard/analytics | Происходит редирект (например, на /dashboard) |
| 3 | Убедиться, что data-testid="analytics-page" отсутствует | Страница аналитики не отрендерена |
| 4 | Выйти и войти как mechanic (role: "mechanic") | Авторизация прошла успешно |
| 5 | Перейти на /dashboard/analytics | Происходит редирект (например, на /dashboard) |
| 6 | Убедиться, что data-testid="analytics-page" отсутствует | Страница аналитики не отрендерена |

Пользователи с ролями manager и mechanic не могут получить доступ к /dashboard/analytics — RoleGuard выполняет редирект. Firestore Security Rules дополнительно блокируют прямой доступ к данным.

### Test Data
```

  { uid: "mgr-001", role: "manager" }

```

## TC-22-008: Таблица сотрудников отсортирована по выручке по убыванию

**Priority:** High
**Type:** Functional
**Related AC:** US-22-3 (#48), FR-12

### Preconditions
- Пользователь авторизован с ролью admin
- Страница /dashboard/analytics открыта, данные загружены (пресет «Всё время»)
- Три сотрудника с разной суммарной выручкой: Коваленко=1000₼, Мельник=800₼, Бондар=900₼

### Steps
| Step | Action | Expected Result |
|------|--------|----------------|
| 1 | Проверить data-testid="employees-report-table" | Таблица присутствует, 3 строки |
| 2 | Считать displayName первой строки (data-testid="employee-row-emp-001") | Первая строка: «Коваленко Олег» (выручка 1000₼) |
| 3 | Считать displayName второй строки | Вторая строка: «Бондар Сергій» (выручка 900₼) |
| 4 | Считать displayName третьей строки | Третья строка: «Мельник Ірина» (выручка 800₼) |
| 5 | Убедиться, что значения выручки убывают | 1000 > 900 > 800 — порядок корректный |

### Expected Result
Таблица сотрудников всегда отсортирована по убыванию суммы выручки (FR-12). Сортировка актуализируется при смене пресета периода.

### Test Data
```
// Суммарная выручка «Всё время»:
Коваленко Олег (emp-001): 400 + 600 = 1000₼
Бондар Сергій  (emp-003): 200 + 700 = 900₼
Мельник Ірина  (emp-002): 300 + 500 = 800₼
// Ожидаемый порядок: emp-001, emp-003, emp-002
